# US14 — les mails de régulation

La construction reste dans le style du groupe : fonctions de domaine, ports asynchrones, handlers recevant un objet de dépendances et factories d'adaptateurs.

## Étape 1 : nommer un fait métier

`stationBoundary` décrit une transition vers vide ou pleine. Une lecture ou reconstruction ne déclenche rien. Une station avec un vélo en panne n'est pas physiquement vide. Le domaine ne connaît aucun mail ni agent.

## Étape 2 : enregistrer un mouvement avec son trajet

`BikeMovementRepository` demande un commit commun du mouvement et du trajet. Le double en mémoire et SQLite l'implémentent ; une vérification de version par instantané refuse une station modifiée entre lecture et commit. SQLite conserve l'historique US12, ajoute le vélo et la date de retour par migration additive et termine le trajet sans supprimer son départ.

`TakeBikeHandler` garde son contrat US6 lorsque `movements` n'est pas fourni, pour préserver les tests précédents. Le parcours réel de station fournit ce port ; `ReturnBikeHandler` le reçoit obligatoirement. Les repositories de trajets et de mouvements doivent partager le même stockage. Les nouveaux tests utilisent cette composition explicitement.
